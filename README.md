# 안심동행 AI

> **2026 금융 AI Challenge**

고령 부모의 위험 송금을 AI가 금융 데이터와 대화 분석으로 탐지하고, 가족이 함께 확인하며, 피해 발생 시 골든타임 대응부터 회복까지 함께하는 가족 금융안전 서비스.

한결은행(부모)·나눔은행(자녀) — 서로 다른 가상 은행 앱 안의 기능으로 구현.
가족이 같은 은행을 쓰지 않아도 연결된다는 점을 데모에서 그대로 보여준다.

---

## 왜 필요한가

대한민국은 2024년 말 초고령사회에 진입했습니다. 보이스피싱 피해는 2022~2023년 감소세를 보이다 **2024년 8,545억원으로 역대 최고치**를 기록, 2025년에는 8월까지만 8,856억원으로 이미 전년을 넘어섰습니다.

**보이스피싱 피해 금액 추이** (억원, 경찰청)

![보이스피싱 피해 금액 추이](assets/voice-phishing-damage.svg)

**60대 이상 피해 비율 추이** (%)

![60대 이상 보이스피싱 피해 비율 추이](assets/elderly-victim-ratio.svg)

- 60대 이상 피해 비율 **30.6%** (2025 상반기) — 전 연령 중 1위, 10년간 피해 건수 **5배** 증가
- 2025년 1분기 기관사칭형 비율 **51%**로 급증 (전년 41% → +10%p)
- 기존 대응은 **방임**(사고 후 발견) vs **성년후견**(자기결정권 박탈)의 양극단

**안심동행 AI**는 이 사이에 존재하지 않던 **중간 단계**를 만듭니다. 감시가 아닌 동행으로, 부모님의 자기결정권을 지키면서 가족이 함께 보호합니다.

> 출처: 경찰청 보이스피싱 현황, 금융감독원 보도자료, 통계개발원 (2025)

## 0~3층 방어선 상세

거래 위험이 없으면 여기서 정상 송금으로 끝난다(4층 AI 의도 분석까지 안 간다). 세 계층 모두
**규칙 기반이며 LLM을 쓰지 않고**, "원시 입력 → 신호 코드 추출 → 코드별 점수 합산"이라는 같은
구조를 공유한다 — 4층(`4-intent-analysis/rules/signals.js`)의 신호 카탈로그 패턴을 그대로
가져온 것이다. 각 계층은 `rules/signals.js`에 `{ 코드: { score, label } }` 카탈로그를,
`agent.js`에는 그걸 호출해 채점을 위임하는 얇은 진입점만 둔다.

```mermaid
flowchart TD
    A[송금 시도] --> B{1층 상대방 검증}
    B -->|화이트리스트 일치<br/>공식 은행·경찰·금감원 번호/도메인| PASS[PASS · 점수 0<br/>2·3층 실행 안 함]
    B -->|더치트 블랙리스트 일치<br/>이미 신고된 계좌·전화·도메인| BLOCK[BLOCK · 점수 100<br/>2·3층 실행 안 함]
    B -->|어느 쪽도 아님| CONT[CONTINUE<br/>+사칭 이름 패턴 의심 시 +30점]

    CONT --> L2[2층 행동 감지]
    CONT --> L3[3층 거래 검사]

    L2 --- S1[예·적금 중도해지]
    L2 --- S2[이체한도 상향]
    L2 --- S3[잔액 반복 조회]
    L2 --- S4[상대방 검증 미실시]
    L2 --- S5[초고속 세션]
    L2 --- S6[반복 뒤로가기]

    L3 --- T1[금액 구간 4단계]
    L3 --- T2[미등록 수취인]
    L3 --- T3[야간 이체]

    L2 --> SUM[오케스트레이터: 1+2+3층 점수 합산]
    L3 --> SUM
    SUM --> GRADE{A~D 등급}
    GRADE -->|A 안전| OK[정상 송금]
    GRADE -->|B~C| MORE[4층 AI 의도 분석으로]
    GRADE -->|D 위험<br/>또는 한도상향+1천만원↑ 강제| HOLD[5분 정지 + 4층]

    PASS --> OK
    BLOCK --> DENY[송금 차단 + db-warning]
```

**1층 — 상대방 검증** (`1-counterparty-verification`): 화이트리스트에 걸리면 즉시 PASS,
더치트 블랙리스트에 걸리면 즉시 BLOCK — 3층의 "0점이면 이후 계층을 실행하지 않는다"는
무마찰 원칙을 1층에도 그대로 적용했다. 둘 다 아니면 CONTINUE로 넘기되, 아직 신고 이력은
없지만 공식 기관 이름을 흉내낸 도메인·전화번호 패턴(`IMPERSONATION_SUSPECTED`)만 추가
점수를 준다. "미등록 수취인" 자체는 3층이 이미 채점하므로 여기서 또 매기면 이중 페널티가
된다 — 실제로 이 버그가 있었고 프론트와 연결하며 발견해 제거했다.

**2층 — 행동 감지** (`2-behavior-detection`): 예·적금 중도해지, 이체한도 상향, 잔액 반복
조회, 상대방 검증 미실시, 초고속 세션, 반복 뒤로가기(`backPresses`) 6가지 신호. 마지막
신호는 프론트가 이미 수집해 보내고 있었지만 채점되지 않고 버려지던 데이터였다.

**3층 — 거래 검사** (`3-transaction-risk`): 금액 구간(100만/300만/1천만/3천만 이상 4단계),
미등록 수취인, 야간 이체 3가지 신호.

**결합** (`orchestrator.js`의 `runDefensePipeline`): 1층이 PASS/BLOCK이면 그 자리에서
등급을 확정한다. CONTINUE면 1·2·3층 점수를 합산해 A(안전)~D(위험) 등급을 낸다. "이체한도
상향 + 1천만원 이상" 조합은 배점 합산 결과와 무관하게 항상 D등급으로 강제한다 — 등록된
수취인 같은 다른 신호와 상쇄돼 낮은 등급으로 새 나가는 걸 막기 위한 안전장치다.

## 사기 송금 의도 분석

의심 송금 상황과 송금 이유를 입력하면, 민감정보를 먼저 전처리한 뒤 RAG 검색과 Text2SQL 조회를 병렬로 수행한다. 이후 금융사기 근거와 개인 거래 패턴을 결합해 LLM이 사기 송금 의도를 분석하고, 위험도와 다음 보호 단계를 JSON 형태로 구조화한다.
